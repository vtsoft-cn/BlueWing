# 启动与密码保存修复

## 最终范围

沿用以前的 Windows 密码保护方式，不新增后台加密服务或解锁操作。名称、服务器、节点 UUID、订阅、路由、DNS、普通配置正常存储；只保护密码、协议密码、私钥、预共享密钥和备份口令。维护者明确不需要兼容之前额外加密的普通字段，选择重新配置。

## 原因与修复

- 上一轮在模块载入时构造核心单例，立即读取数据库，发生在 Electron ready 之前。Windows 密码 API 此时不可用，异常沿构造函数抛出导致主进程错误窗口。核心初始化和事件绑定已移到 ready 后；测试直接加载真实主进程入口，验证没有提前读库。
- 打开和关闭未修改的配置不再自动加密迁移；取消普通字段和整块配置的额外加密。旧普通字段的加密串被跳过并提示重新配置，不做兼容解密。
- 密码读取失败时界面仍打开，正常记录可用；手动输入的密码可用于本次连接，原文件不被空值覆盖。无法保存时显示普通提示，不再提供新增的解锁操作。
- 公司 VPN 无法记住密码或登录会话时仍可用手动密码连接，不因缓存写入失败终止登录。
- 保存失败不再跳过核心停止和代理恢复。回归模拟退出时磁盘错误，验证其他清理步骤仍执行。
- 目录限权只修改 DACL，不更换目录所有者，避免普通用户权限不足；仍限制其他账号访问临时凭据。
- 普通配置导出可不填口令，只有选择包含密码的完整加密备份时需要口令。

Windows ready 时机依据：[Electron safeStorage 文档](https://www.electronjs.org/docs/latest/api/safe-storage)。使用的是既有密码 API，没有另外安装或启动服务。

## 现场处理

当前系统代理由另一款软件提供，端口为 7890；实测 Google 返回 204、GitHub 返回 200。没有发现 BlueWing 进程、TUN 或其残留默认路由。本轮未改系统代理、路由、DNS，也未停止另一款 VPN。

旧版数据有一条节点的 UUID 仍为上一轮的加密串，旧版会将其当作认证参数。按维护者重新配置的选择，备份主配置、备份配置、Local State 和 VPN 配置/凭据文件后移除该异常节点，关闭自动连接。其他 VPN 配置未删除。备份在 `%APPDATA%\BlueWingConnect\recovery\before-reconfigure-<时间>/`。这不验证远端节点本身；重新添加有效节点后再验证 BlueWing 公网出口。

后续重新配置节点后，同一节点及运行配置在隔离端口访问 Google 返回 HTTP 204。维护者随后手动切换到 BlueWing，明确通过 `127.0.0.1:2080` 请求 Google 的 `generate_204` 地址，结果同样为 HTTP 204，确认当时 BlueWing 的公网转发正常。之前日志中出现过节点域名 DNS SERVFAIL，触发原因尚未确认；本次成功不作为该偶发问题已经修复的证据。

## 验证

- 229 项应用回归通过，包含密码/密钥保护、普通字段正常存储、旧普通字段不兼容、失败时文件保留，以及手动密码不被保存失败阻断。
- 真实主进程入口覆盖正常读取、密码 API 不可用、旧格式需重配、退出保存失败四种情况。界面可打开，未提前读库，原文件保留，退出仍执行代理恢复。独立目录与网络操作替身避免接管当前网络。
- 24 项真实核心集成通过；生产渲染器安全边界、普通用户目录限权、VPN 状态和完整界面分别回归。
- 新包为 `BlueWingConnect-StartupFixed-Setup.exe`，不自动覆盖当前安装，不自动切换正在使用的 VPN。
