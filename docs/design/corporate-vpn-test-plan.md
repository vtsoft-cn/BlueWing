# EasyConnect / aTrust 集成：测试与验收计划

日期：2026-10-23；配套：[详细设计](corporate-vpn-integration-design.md)、[开发步骤](corporate-vpn-implementation-plan.md)。本文件是待执行计划，表格中没有任何一项因写入文档而被视为通过。

## 1. 验收原则

1. 同时证明公司目标到达企业核心、国内目标使用 DIRECT、公网目标仍使用原公网代理。网页能开但出口错误，不算通过。
2. 读取数据库、生成文件、实际连接证据三者；不能只检查界面绿点或 JSON 文件。
3. 认证成功、端口监听、隧道可用、指定资源可用分别验证。
4. HTTP 302 要继续跟随跳转；403/401需要区分服务响应与授权失败；TCP通不代表SSH握手成功。
5. EasyConnect 与 aTrust 独立出报告。aTrust 缺实机环境时标记 BLOCKED，不能用 EasyConnect 的结果替代。
6. 系统代理模式和 TUN 模式分别验收。ping 不通不能直接判 SOCKS 失败；普通 curl 不通也可能是它没有使用系统代理。
7. 真实 OTP、验证码、密码由用户操作，不放到测试源码、录像、CI、失败断言和日志中。

## 2. 测试分层与环境

### 2.1 L0：纯逻辑测试，默认 CI 执行

- TypeScript：配置校验、规则编译、状态机、IPC DTO、保险库契约、迁移与导入。
- Go：控制协议、挑战回调、资源转换、拨号策略、DNS策略、会话序列化。
- 全部使用隔离数据目录和假凭据，禁止回退真实 APPDATA。
- 使用 fake timer 进行退避、OTP过期和睡眠恢复测试，不把每条测试真的等待几分钟。
- 原项目测试必须保持通过；基线为 80 项。新增测试必须在 npm test 的入口中实际执行，当前入口是手工列举文件，不能只新建文件却漏加。

### 2.2 L1：本机模拟集成，默认 CI 可执行

模拟服务至少包括：

| 服务 | 用途 |
|---|---|
| 假企业核心 | 按控制协议发 ready/challenge/resources/error，支持故意拆帧/退出/迟到事件 |
| 假 SOCKS5 服务器 | 校验内部账号、记录ATYP、域名/IP、端口、连接数与错误码 |
| 假公司 DNS | 记录查询，返回固定映射、NXDOMAIN、SERVFAIL、AAAA空结果、TTL及延迟 |
| HTTP 企业服务 | 返回200/302/401/403，重定向到同域和另一个公司域名 |
| SSH banner 服务 | 返回合法SSH banner；另设只接受TCP但不发banner的假服务 |
| 公网长连接服务 | 支持WebSocket、SSE或持续TCP回显，记录唯一连接ID和序列号 |
| 直连/公网代理记录器 | 接收允许的流量，任何公司目标/公司DNS出现都使测试失败 |
| 假保险库 | 可模拟加密不可用、密文损坏、错误Windows用户、保存失败 |

模拟核心协议不等于模拟完真实深信服认证：L1 验证本产品编排，真实兼容性还要 L2/L3。

### 2.3 L2：固定 sing-box 二进制集成

使用安装包内将分发的 sing-box 1.14.3；仅启动隔离 loopback 端口，不改本机系统代理/TUN。校验本地 rule-set watcher、SOCKS域名传递、固定出口、长连接和错误分支。

每次启动记录exe版本、SHA256、PID、配置hash、rule-sethash。测试结束仅结束该测试拥有的PID、关闭监听并删除隔离目录。机器上已有 BlueWing/EZ4Connect 时也不得互相终止。

### 2.4 L3：真实 Windows 验收，人工选择执行

环境：Windows 11 x64为必须；Windows 10及ARM64为各自声明支持时的额外矩阵。至少覆盖普通桌面用户、同一用户提权运行、中文/空格路径、已安装版、便携版。

需要：一个实际 EasyConnect 网关和一个实际 aTrust 网关、对应授权账号、可用公司资源、一个本地 LAN 目标、一个国内站点、一个可经公网代理访问的目标。短信等方式还需要服务端确实开放。

**先使用隔离配置完成模拟测试；只有用户明确开始实机验收后才切换系统代理/TUN。** 不在开发脚本中自动改正在工作的网络。无需虚拟机，可在当前物理机的受控验收时段执行。

## 3. 测试数据与隔离约定

共享/提交到Git的样例使用：

- 网关：`vpn.corp.example:443`；开发 `dev.corp.example`、测试 `uat.corp.example`。
- 样例公司段：`10.20.30.0/24`；样例办公室 LAN：`192.168.50.0/24`。
- 单标签名 `gitlab`；中文显示名称；IPv6网关 `[2001:db8::10]:443`。
- 仅测试用字符串密码，不复用真实登录信息。

真实网关、公司地址和期望响应放在本机验收表，不提交到公共测试夹具。公网真实服务可能限速或拒绝自动化请求；自动测试依赖本机mock，人工公网验收再记录真实结果。

## 5. P0必须先执行的核心实验

### 5.1 本地规则集更新不重启公网核心

1. 使用固定sing-box二进制，创建独立mixed端口、两个mock出口及本地source rule-set。
2. 先建立一条到公网mock的长连接，每秒发送序列号，记录连接ID和sing-box PID。
3. 将 `dev.corp.example` 从普通路径更新为公司路径，分别测试文件原位写入和临时文件替换；Windows生产只选验证成功且无半写风险的方法。
4. 不调用核心restart、不请求Clash `PUT /configs`；等待有界watch窗口，再发新公司请求。
5. 断言新公司连接到正确mock，公网连接ID与序号连续，PID不变。
6. 测试损坏文件、快速连续更新和增加IP条件的metadata变化；记录旧策略是否保留及如何确认应用。
7. 若失败，停止宣称R07已满足，写ADR评估修复watch/适配核心版本；不能用“返回204”或偷偷restart过关。

### 5.2 认证输入与严格隧道拨号

1. 核对上游固定提交的EasyConnect/aTrust输入位置、资源接口、日志和会话文件。
2. 证明能以回调获取动态码/短信/验证码，不将密码放在CLI；证明取消会终止认证网络任务。
3. 在fake core/受控环境模拟未命中资源及解析失败，断言企业拨号路径没有物理DIRECT后备。
4. 真实网关验证只由用户完成认证输入，记录服务端版本与能力，不记录会话token。

## 6. 手工实机步骤

### 6.1 通用准备

1. 记录BlueWing、sing-box、企业核心版本和hash；备份当前非机密配置及系统代理所有权快照。
2. 外部EZ4Connect/其他同端口代理先断开；程序应检测端口冲突，而不是直接结束外部进程。
3. 保留原公网主节点，确认国内网页和公网代理可用。
4. 配置三个目标：公司HTTP/HTTPS、公司SSH、本地LAN；未知生产IP保持未知。
5. 先系统代理模式，TUN关闭。选择协议并发现/选择认证方式。

### 6.2 EasyConnect

1. 输入正确网关和端口；密码只在本地输入，完成手工动态码/图片挑战。
2. 确认UI显示认证、隧道、端口、规则各阶段；两国内直连仍开启。
3. 从内置诊断请求公司网页和SSH，跟随完整HTTP跳转。
4. 在Edge打开同一目标；用显式代理curl作对照。
5. 保持公网长连接，断开/重连公司；关闭企业核心注入一次故障。
6. 完成TUN章节，验证普通curl和ssh，不再给它们配置SOCKS。

### 6.3 aTrust

1. 新建aTrust配置，“获取认证方式”；记录返回的authType/loginDomain，不把真实账号写报告。
2. 优先执行服务端开放的账号密码方式；如要求二次挑战，验证状态保持等待用户。
3. 执行短信方式，测试错误码、倒计时、一次重发和取消，不为压力测试反复向真人发短信。
4. 有CAS等真实方式时单独验收回调来源、state、成功/取消；无条件时标BLOCKED。
5. 选择记住会话后重启，验证恢复与过期；取消记住后确认不再恢复旧会话。
6. 验证资源和DNS、线路刷新、断线恢复以及TUN下网关不回环。

### 6.4 TUN与全应用

1. 完成已有管理员提权流程；核对实际TUN网卡及唯一接管者为sing-box。
2. 关闭系统代理（按已有互斥联动处理），执行普通curl、原生ssh并观察正确公司出口。
3. 同时访问国内、本地LAN和公网，并保持GPT/Codex实际会话。
4. 公司断开、核心退出、OTP重新认证时，公网连接保持，原公司目标明确失败。
5. 最后关TUN并验证原系统代理状态、用户数据位置和运行状态一致。

## 7. 命令参考与解释

以下仅是验收时手动使用的命令；端口以产品实际显示值为准，示例网关/域名不是真实服务。

```powershell
# 系统代理模式：明确通过 BlueWing，而不是依赖 curl 读取 Windows 设置
curl.exe -v --connect-timeout 5 --max-time 15 -x http://127.0.0.1:2080 http://dev.corp.example/

# 跟随重定向；诊断导出必须剔除Cookie及Location中的敏感query
curl.exe -L --max-redirs 5 --max-time 30 -x http://127.0.0.1:2080 http://dev.corp.example/

# TUN模式：不加代理参数，验证系统级接管
curl.exe --connect-timeout 5 --max-time 15 http://dev.corp.example/
ssh -v -o ConnectTimeout=8 testuser@10.20.30.40

# 只检查本地监听，不代表VPN隧道已可用
Get-NetTCPConnection -State Listen | Where-Object LocalPort -in 2080,11080,11082
```

不要把 `Test-NetConnection`、ping、监听端口成功当作完整代理验收。测试HTTPS时保留证书校验，不用 `-k` 把产品TLS问题掩盖掉。SSH实机操作只需验证握手/用户授权的登录，不执行远端写入命令。

## 8. 结果格式与发布门槛

每次运行输出机器可读报告，至少包括：

```json
{
  "runId": "example-run",
  "build": {"bluewingCommit":"...","vpnCoreCommit":"...","singBoxVersion":"1.14.3"},
  "environment": {"os":"Windows 11 x64","takeover":"tun","elevated":true},
  "cases": [{"id":"I09","status":"NOT_RUN","evidence":[],"reason":"待执行"}],
  "capabilities": {"easyconnect":{},"atrust":{}},
  "secretsRedacted": true
}
```

发布必测：U、B中已声明支持认证的用例、I、W、F全部执行；R提供测量记录。CAS未开放时B11可以BLOCKED，但发行能力必须明确不宣称该方式已支持；aTrust基础登录/资源/TUN不能全部BLOCKED后仍声称“已完成aTrust”。

以下任何一项失败都阻止宣布正式完成：

- 公司目标或公司DNS出现在公网/DIRECT记录器中；
- 公司连接/断开重启公网核心或切换公网主节点；
- 需要关闭国内规则或手工重排JSON才能访问；
- 真实秘密进入日志、argv、备份、renderer查询或明文会话文件；
- 核心未运行却显示已连接，或仅用302/端口成功代替完整验收；
- 仅系统代理可用，却把不配置代理的curl/SSH标成全应用完成；
- 产品安装包仍依赖外部EZ4Connect或开发机中的核心文件。
