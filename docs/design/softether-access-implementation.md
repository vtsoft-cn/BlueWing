# SoftEther 原生接入与三种通用分流模式

实现日期：2026-10-26。此文补充既有 VPN 接入设计；不包含账号密码、口令摘要或会话密钥。

## 接入方式

- 在「VPN 接入 → 新增接入」选择 SoftEther，配置网关、端口、Virtual HUB、账号和密码。
- 支持标准密码挑战认证，以及显式选择的 RADIUS / 域账号密码认证。密码仅经继承管道传给核心，可用 Windows 系统加密保存。
- 使用原生 SoftEther TCP/TLS 协议，不依赖官方 VPN Client 服务、TAP 网卡、虚拟机或 Docker。
- 复用当前 VPN 核心的私有 gVisor 网络栈和 SOCKS/DNS 接入层。不修改 Windows 默认路由、网卡优先级或系统 DNS。
- 网关证书复用现有自动处理 / CA / 固定指纹逻辑，不默认无条件跳过校验。
- 不会主动断开、删除或更改官方客户端账号；测试时应由用户断开官方客户端，避免其既有全局路由影响公网出口。

## 资源与分流

SoftEther 不提供 EasyConnect 式的授权资源目录。连接时从 DHCP 获取虚拟 IPv4、掩码、DNS 和 classless route 提示；虚拟网段和非默认 classless routes 可形成接入资源。DHCP 默认路由不会写入 Windows，也不会转成全流量规则。

其他公司网段不能从虚拟地址自动推断，也不应硬编码进产品。新增智能私网路径识别后，未知私网 TCP 目标可按实际访问先验证本机、再尝试当前 VPN；仅保存成功的精确 IP 和端口，不推断整段所有权。公网公司地址、特殊域名和地址冲突仍可在「高级分流」明确配置。完整优先级、缓存和断线边界见 [automatic-private-routing.md](automatic-private-routing.md)。

所有协议均可在每条接入的「高级分流」选择 `trafficMode`，缺省为用户确认的 `split` 智能分流：

| 模式 | 国内公网 | 公司资源 | 国外网站 | 其他局域网 |
| --- | --- | --- | --- | --- |
| 智能分流（默认） | 本机直连 | 对应 VPN | 已开启的代理；无代理时本机 | 本机优先；未知私网 TCP 本机不通时尝试当前 VPN |
| 全部走 VPN | 对应 VPN | 对应 VPN | 已开启的代理优先；无代理时 VPN | 对应 VPN |
| 自定义 | 用户选择 | 对应 VPN，优先级最高 | 用户选择 | 用户选择 |
| VPN 已断开 | 恢复原规则 | 已知目标阻止，避免泄漏 | 恢复原规则 | 恢复原规则 |

“全部走 VPN”保留用户确认的例外：开启公网代理时，国外网站仍优先走代理。自定义可以分别选择本机、VPN、公网代理；选择代理但未配置 / 未启用节点时按界面说明直连，已配置节点故障不会静默回退直连。

域名依据内置 `geosite-cn` 和 `.cn` 后缀，IP 依据内置 `geoip-cn`，不以网页语言或服务器所属公司推断地区。

优先级：明确阻止 → VPN 核心物理出口 → 各公司的有效资源 → 公司保护规则 → 用户明确的公网域名/IP 规则 → 当前 VPN 的私网 TCP 路径识别 → 已识别精确端口断线保护 → 当前模式的 LAN/国内策略 → 原 LAN/国内及应用例外 → 当前模式的国外兜底。回环端点保留直连。

选择 VPN 出口不增加网关授权。部分网关不允许访问公网，因此默认智能分流将普通公网分离到本机 / 代理，VPN 只承担公司资源。明确选择全 VPN 或自定义 VPN 出口的流量仍由网关授权决定，公司目标失败不会回退公网。

通过本地 source rule-set 文件启停当前模式；已安装同一运行配置后，连接 / 断开无需重启 sing-box。路由和 DNS 使用独立活动标记，DNS 标记不含 IP 过滤字段，避免 sing-box 1.14 热更新报错。新增接入或修改模式保存后，下一次点击「连接 VPN」会自动准备必要的分流配置，保存操作不重连当前代理。模式与自定义出口按接入保存、备份保留；连接期间可只读查看。旧预览版 `routeChina` 忽略，并清空旧活动文件，防止旧规则继续接管公网。

页面显示公司 / 国内 / 国外三类实际出口和代理节点状态；资源区区分网关下发、SoftEther 网络发现和用户补充。EasyConnect / aTrust 自动读取资源；SoftEther 无法推断所有公司网络，用户只知道一个业务网址也能补充（自动提取 http(s) 域名）。完全没有目标信息时不猜测所有私网都属于公司。

## 生命周期与边界

- TLS 与登录 / DHCP 建立总期限 30 秒，外层接入管理仍有认证超时及连接代次检查。
- 取消连接关闭待连接及活动 socket；读写队列均有上限；异常后触发现有有限重试流程。
- DHCP 在租期一半开始续租，到期或 NAK / 地址、网关、DNS、路由变化会关闭隧道，交由管理器重新连接并重新发布资源。
- 每 10 秒发协议保活；每次底层 TLS 读取更新空闲超时，避免仅有保活包时误判断线。
- ARP 请求解析下一跳；只把发给当前虚拟 IPv4 的数据包交给网络栈，不广播业务 IP 数据。
- HTTP 头、PACK 元素 / 长度及以太网帧均有边界，畸形报文返回错误。
- 公网核心启动等待由 5 秒调整为 20 秒；进程真实退出仍立即失败，降低慢机器 / 网卡切换时误杀后自动重连的概率。

当前 VPN 代理入口支持 IPv4 TCP。DNS 可以通过私有栈使用 UDP，但不开放 SOCKS UDP / ICMP / IPv6 隧道。选择 VPN 出口的非 TCP 流量会被拒绝；浏览器 HTTP/3 通常回退 TCP。本机和公网代理流量按原核心能力运行。要接管不读取系统代理的软件，仍需启用 BlueWing TUN 或指定应用代理；图标本身不作为通断判断依据。

## 来源与兼容

MIT 源码基线：govpn v0.2.4，提交 `78c78a37330f361c8f4922b0e7e126a3fc495742`。仅引入 SoftEther 报文、认证及 DHCP / Ethernet helper，复用项目原有 Go 1.25.6 与 gVisor，不引入另一套网络栈。见 `native/vpn/client/softether/UPSTREAM.md` 和 `LICENSE-MIT`；许可证、完整维护源码随核心打包。

客户端产品标识为 BlueWing，协议兼容基线为 SoftEther 4.38 build 9760。真实网关首次验证发现上游库的 1.00 / build 1 字段导致官方错误 87；修正协议基线后通过认证。高于现有兼容范围的服务端最低版本要求会明确报错，不自动尝试任意版本号。

不支持 UDP 加速、多 TCP 并行、半连接、桥接、匿名 / 证书 / SSO 登录界面。整体许可证发布决策沿用既有项目要求。

## 已做验证

自动验证：

1. `npm test`：包括 SoftEther 配置校验、三种模式 / 自定义出口持久化、旧开关迁移、公司隔离、启停恢复及配置幂等。
2. `npm run test:vpn-core`：认证成功 / 错误密码 / HUB、TLS 名称拒绝、DHCP、ARP、取消待认证、队列关闭、短租期续租、报文边界，以及既有 EasyConnect / aTrust 回归。
3. `npm run test:vpn:integration`：真实 sing-box、隔离端口、模拟公司 / 代理 / 本机出口；覆盖公司 VPN 拒绝公网的智能分流、全 VPN 的国外代理优先、无代理时全 VPN、自定义出口、断开恢复、公网 PID 不变、公司断线阻止和无节点到代理的切换。
4. `npm run test:vpn:ui`：真实 Electron 渲染，检查三出口页面、SoftEther 新增、三种模式、自定义出口保存重开、网址提取域名、只读及原有认证交互。
5. `npm run build`、`npm run build:vpn-core`、sing-box `check`。

真实网关验证（本机隔离测试，不通过官方 VPN Client）：

- 证书检查、标准密码挑战认证、DHCP 获取 `192.168.30.0/24` 地址和 VPN DNS 成功。
- 经原生私有栈连接 `192.168.110.178:22`，收到 OpenSSH banner。
- 经同一原生隧道解析并访问国内网页，收到 HTTP 200。
- 隧道空闲 65 秒后再次经 VPN 访问 SSH 成功，排除仅有保活包时的误超时。
- 测试后官方客户端仍离线，原有 BlueWing `2080` 公网代理访问返回 HTTP 204。
- 实测借用官方本地已保存的密码摘要，经匿名管道交给仅用于测试的 Go overlay 核心；不读取明文、不把摘要写入磁盘。正式发行核心不包含测试认证旁路。正常明文到密码挑战转换由协议单测覆盖；正式 UI 登录仍需用户验收。

2026-10-26 补充实机验证：用户在正式 UI 中连接 SoftEther 后，测试 `192.168.110.45:22`，经统一应用代理 `127.0.0.1:2080` 和内置 SoftEther 入口均收到 SSH 欢迎信息。未开启 TUN 时系统直连超时；用户开启 TUN 后，无应用代理的系统 TCP 连接也收到相同 SSH 欢迎信息。国外无显式代理参数的 HTTP 测试返回 204，国内 HTTP 测试返回 200。这证明此环境下的基本 TUN / SoftEther / 公网代理组合可用，不代表所有公网服务或网关策略均兼容。

切换网络期间曾出现网关 `5555` TCP 超时，换网后证书探测及用户登录恢复；尚不能把该现象归因为单一客户端缺陷。多网卡检测和自动出口刷新仍需独立验证。

未验证：真实 RADIUS、长期真实网关续租、会话不断开的多网络漫游、其他公司的最低版本与访问策略。

## 用户验收步骤

1. 断开官方 SoftEther VPN Client，退出旧版 BlueWing，运行新测试包。保留旧账号作为回退。
2. 首页可以选代理节点，也可以选本机直连。测试国内 / 公司访问不需要公网节点。
3. 新增 SoftEther，填写自己的网关 / 端口 / HUB / 账号密码，可选择加密保存。
4. 智能分流默认开启「自动识别私网目标」。验证未填写手动规则的实际私网服务器；首次访问先尝试本机，失败后走当前 VPN。公网公司地址、特殊域名和同地址冲突时在高级分流明确配置，不从单个 IP 推断整段公司网段。
5. 保持默认「智能分流」，或显式选择「全部走 VPN」 / 「自定义」，保存后直接点击「连接 VPN」。首次接入或修改模式时自动更新分流，可能短暂重连现有公网连接；配置未变化时跳过。
6. Xshell 使用界面显示的应用代理（通常 `127.0.0.1:2080`），浏览器使用 BlueWing 系统代理。要让无参数 curl / SSH 被接管，在首页打开 BlueWing TUN。
7. 检查公司 SSH / 网页、国内域名 / IP、GPT / 国外网站及本地 LAN。ping 不作为 TCP 接入的验收依据。
8. 断开 VPN 后检查公网恢复原出口、GPT 继续可用、已知公司资源被阻止；重启确认模式和自定义范围保留。
9. EasyConnect / aTrust 也可在各自高级分流选择同样的模式；选择 VPN 公网出口前先确认网关允许访问。

回退：断开内置 VPN 并恢复原开关 / 退出测试版；原官方客户端账号和路由配置未经本功能修改。
