# 智能分流的自动私网路径识别

日期：2026-10-26。目标是补足网关资源目录不完整时的私网访问，同时保持普通公网本地直连、国外按现有代理策略访问。

## 判断依据与边界

网关可能只下发 VPN 自己的虚拟网段，而没有给出背后的所有业务网段。不能把“已连接”当作“公司资源已经全部识别”，也不能从一个可达 IP 推断整个 /24 属于公司。

资源分两类：手动配置、网关明确下发的目标属于强规则；自动探测结果只是当前 IP、端口和 TCP 协议的路径观察。可达性不能证明公司归属；两侧同地址同端口都可达时默认保留本机路径，用户可通过明确公司规则指定 VPN。

自动识别只在智能分流中启用，默认开启，每条接入独立保存开关。明确设置关闭的旧配置保持关闭。全部走 VPN、自定义模式沿用各自明确选择，不被自动识别改写。

## 路由顺序

1. 明确阻止、VPN 核心物理出口、用户公司规则和网关授权资源及其保护规则。
2. 用户明确的普通域名/IP 出口规则。
3. 当前已连接 VPN 的自动私网路径判断。
4. 本次连接异常中断时，对已通过 VPN 到达的精确 TCP 目标保持保护。
5. 原有局域网、国内公网、应用和国外代理策略。

自动判断范围仅为 RFC1918 IPv4：10/8、172.16/12、192.168/16。排除公网、回环、链路本地、组播、IPv6 和 FakeIP 地址。UDP/ICMP 不通过自动 TCP 接入。公司公网地址不因直连失败而被自动判为公司资源。

## 按访问判断路径

- 只处理用户实际发起的目标连接，不扫描网段，不轮询其他端口。
- 先通过物理网络尝试该 TCP 目标，期限 800 毫秒。可达时复用已建立的本机 socket，不发送第二次业务请求，不进入 VPN 隧道。
- 本机不可达时尝试当前 VPN。两侧都失败就返回连接失败，不尝试其他公司或公网代理。
- 只有选定连接成功后才回复 SOCKS 成功并转发业务字节。连接建立后的失败直接报告给应用，禁止中途切换出口或重放请求。
- 已知公司目标始终走 VPN，不因 VPN 失败回退本机。受限端口、仅保护资源以及已有公司 DNS 租约也不能借自动识别扩大权限。
- 对已解析为私网的域名，按绑定物理接口的 DNS 解析；本机解析不可用时才查询当前 VPN DNS，最终仍要求结果属于 RFC1918 IPv4。尚不能解析的公司特殊域名仍需配置，不能以名称猜测归属。

## 缓存、断线与换网

原生进程只保存当前会话的 IP:端口提示，上限 256，单条一分钟有效。新会话不沿用旧提示；提示过期后重新判断本机路径，避免换网后一直绑定旧出口。正在使用的连接保持原出口直到关闭。

主进程保存通过 VPN 成功建立的精确 /32 + TCP + 端口记录，绑定接入 ID、协议、网关、端口、账号、登录域和认证方式。这些历史记录用于界面展示及本次连接异常中断时的保护，不在重连时直接当作确定的 VPN 所有权规则：新会话仍重新检查路径。本机恢复可达后撤销相应历史记录。

已识别目标的断线保护保留精确协议和端口，不扩大到整个主机或网段，不混入原有公司目标的全端口保护集合。不同公司记录隔离；当前活动接入可以重新识别其他公司的旧私网地址，明确配置的公司资源仍优先。

2026-10-27 修正启停边界：保存配置不代表启用接入。未连接的接入不发布有效的路由、DNS 接管或保护规则。连接准备阶段只保护正在连接的接入，隧道就绪后才启用转发；异常掉线及重试期间可保留本次接入的保护，界面明确显示，并可点击“恢复普通分流”停止接入。主动断开、取消连接、初次认证被拒绝时清除相应接管与保护；程序升级或重开时保留节点、VPN 配置、凭据、分流模式及历史记录，但清空上一进程的运行规则，待本次真实登录成功后重新启用。历史缓存不能使未连接的公司持续拦截普通公网。

本机路径的存量连接归代理入口管理，断开 VPN 不关闭这些未进入隧道的 LAN 连接。退出程序、重建入口时仍会正常清理。记录写入失败只记录本机诊断，不因此断开正常 VPN。

## 界面

- 智能分流中显示“自动识别私网目标”开关、首次访问可能略慢的说明，以及公网公司地址和地址冲突的手动入口。
- 资源列表明确区分用户自定义、网关/网络发现、自动识别；自动识别显示精确端口和 TCP。
- 显示每个接入的识别数量，并提供清空入口。连接期间只读；断开后可清空，保留手动规则和凭据。
- 关闭自动识别后恢复原来的手动/网关资源分流。保留的历史记录可查看和清空，但不继续接管流量。
- 观察记录保存在当前数据目录的 vpn-runtime，不将其硬编码进应用，不放进安装包或配置备份，不保存业务内容。

## 验证

1. 原生：本机路径复用、未接触 VPN、800ms 上限、本机失败后 VPN、精确端口缓存、过期重判、取消、公共/特殊地址不探测。
2. 原生：已知公司端口及 DNS 租约保护不可被自动识别绕过；本机连接跨 VPN 断开仍可读写，入口关闭后全部释放。
3. 主进程：开关迁移/保存、精确目标记录、网关隔离、无效事件和旧代次拒绝、重启恢复、清空不影响手动规则、缓存失败不杀 VPN。
4. 真实 sing-box：活动 VPN 的未知私网进入自动判断，普通国内/国外目标从不进入公司探测；明确规则优先；异常掉线只阻止已学到的具体端口，主动断开恢复普通分流。
5. Electron：开关保存重开、识别记录来源/端口、只读和清空、左右独立滚动及最小窗口。
6. 实机：不填写测试服务器的手动目标，以隔离原生核心验证本机不可达、VPN 可达的 SSH 握手；另外检查国内本地和国外代理，保留未完成的长期/换网验证状态。

## 本次验证结果

2026-10-26：应用测试 131 项、真实 sing-box 集成测试 12 项、原生 Go 核心测试和 Electron 界面检查全部通过。集成覆盖国内本机、国外代理、未知私网自动入口、已识别精确端口断线保护，以及清空记录后的恢复；原生覆盖本机失败后 VPN 回退、缓存到期、授权端口保护和连接生命周期。

2026-10-27：应用测试增至 133 项，12 项集成测试及 Electron 界面检查通过。新增启动时旧规则清理且配置文件内容不变、初次认证失败释放接管、已建立连接异常中断保持保护、手动停止恢复普通分流，以及未连接的 VPN 不拦截已保存的公网目标。实机已解除该类误拦，用户确认正确端口的网站恢复打开。

隔离实机测试使用正式编译的原生核心、已有加密凭据和已保存的证书指纹，未修改当前接入配置及系统路由。手动目标和固定解析均为空，访问真实私网 SSH 服务器收到 OpenSSH 欢迎信息，观察到本机路径；断开测试 VPN 后此连接继续保持。当前物理网络本身可达该服务器，因此异地真实 VPN 回退尚未完成实测；长时间业务连接和实际换网验证也保留为待验收项。自动回退已由受控连接测试覆盖，不能据此宣称所有实际网关都已验证。
