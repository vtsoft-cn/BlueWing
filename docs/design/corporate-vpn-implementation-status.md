# VPN 接入 集成：实现状态与实机验收

更新日期：2026-10-23。本文补充现有设计、实施计划和测试计划，区分已完成的代码与尚未执行的真实网关验收。

## 自动证书与密码保存

按用户后续要求，默认改为自动处理证书：先读取网关证书，再发送登录信息。公共 CA 证书继续校验系统信任链，并允许正常续期；首次出现未受信任的签发者时，将证书指纹绑定到当前网关（TOFU）。首次记录本身不是独立的服务器身份验证，适用于用户确认网关地址后的首次连接。此策略同时用于 EasyConnect 连接和 aTrust 认证方式发现。

已记录指纹发生变化、曾使用可信 CA 的网关降级为不可信证书、证书过期或尚未生效时停止认证，不自动覆盖记录。显式 CA 不回退到自动信任。取消操作后不继续绑定证书或发送密码；更换网关、协议、SNI 或 CA 时清除原自动绑定。高级选项保留严格模式和手动指纹处理。

连接面板支持「加密记住密码」和「保存密码」，可以在登录成功前保存；勾选时已有密码会立即加密保存，之后输入的新密码也可单独保存，或在连接时保存。再次连接可留空，取消勾选会删除此接入的密码。密码按网关、协议、账号和认证域绑定，渲染层只收到是否已保存的布尔状态，不回传密码。不保存动态码；系统加密不可用时禁止启用记忆。

## VPN 接入页面改版

入口统一命名为「VPN 接入」。主页面分为接入配置列表与连接面板，连接、密码和状态在首屏显示；配置编辑移入分组弹窗，包含连接设置、分流范围和高级选项。列表支持按名称、网关和协议搜索；认证弹窗保留独立的全局入口。

协议名称、标记和 UI 能力统一放在 `src/renderer/vpn/providers.ts`。通用表单和连接视图不再按公司场景命名；后续增加协议时，需要同时提供原生协议适配与相应能力定义，不能仅增加一个选项就宣称支持。

此次保留现有 `corporateVpn` IPC、配置文件与备份字段，不迁移或重写用户保存的配置名称。新增、编辑、取消未保存更改、aTrust 认证发现、证书读取及动态码交互通过隔离 Electron 测试；并检查 1200×780 和 980×680 窗口的横向溢出。

## 应用代理入口

「VPN 接入 → 应用代理」展示供 Xshell 等软件使用的 SOCKS5 类型、回环地址和当前混合监听端口，并分别提供地址、端口复制按钮。端口来自 App 的实时设置及设置变更通知，不使用 VPN 协议核心的内部端口；代理运行状态来自公网核心状态事件。修改设置或导入备份后，页面随共享状态刷新，Xshell 的既有设置仍需用户同步修改。

代理未运行时提示先连接首页代理；开启入站认证时提示在设置中查找账号密码，不在卡片或复制文本中展示凭据。未开 TUN 时说明 Xshell 需要显式代理。界面验证覆盖端口更新、复制、复制失败、停止状态和认证提示；使用隔离 IPC，不改动正在运行的用户网络。

## 按接入保存的高级分流

每条公司/网关接入的资源区提供「高级分流」入口。用户可选填自定义域名、IP/网段和固定域名解析；这些值保存在该接入的 `targets` / `hosts` 中，重启继续加载，与其他接入隔离。服务器资源不覆盖这些字段；留空时保留服务器自动分流。连接期间可以打开各个配置页查看，字段只读，保存、删除和凭据修改不可用。修改前先断开 VPN，保存后重新连接即可加载；只有新增/删除接入或端口重分配才需要完整应用分流。

顺序为明确阻止 → 当前接入的用户自定义 → 当前接入的服务器资源 → 原有通用规则。原生 DNS 应答及 SOCKS 域名解析均优先使用该接入的用户固定解析，再使用服务器记录/企业 DNS。资源列表将用户配置放在服务器下发之前展示。配置中不内置任何公司的域名或 IP。

回归验证包括自定义规则落盘后重新实例化加载、同名服务器记录被用户覆盖、其他公司不继承用户规则、打开高级分流后保存及重新打开。用户已确认本机 EasyConnect 登录成功；只读探测取得公司 SSH 服务响应。Windows TUN 和完整业务登录仍需独立验收。

## 验证码与凭据交互

连接设置提供可选密码输入；填写后自动选择加密记忆，点击保存配置时通过独立凭据接口保存。密码不写入接入对象、备份或日志，不回显已保存内容。留空保留当前凭据；取消密码记忆时清空本次输入，保存后清除已有凭据。若配置保存成功但系统加密保存失败，保留配置 ID 和输入供重试，并明确提示部分失败。

验证码请求以接入 ID、连接 generation 和挑战 ID 共同区分。取消连接后使旧定时器失效，重新连接收到新请求后从该请求的有效期计时，并清空上一轮输入、点选和提交状态。超时回调同时检查连接代次和定时器版本，后续认证步骤不会被旧定时器终止；验证码超时使用独立错误码。

弹窗支持关闭按钮、Escape 或「稍后填写」收起，保留输入和同一请求的截止时间，点击「继续填写验证码」恢复。收起不延长服务端请求的有效期；只有取消连接后重新发起认证才开始新一轮。已过期或重复提交在界面及主进程均被拒绝。已收起但过期的请求仍由主进程正常结束。

## 不依赖代理节点的 VPN 接入

无节点时允许直接启动本地分流服务，默认让普通公网、DNS 和局域网使用本机直连；公司资源继续由当前 VPN 的授权与自定义规则接管。首页提供「启动直连分流」，不再强制跳转订阅导入。保存接入后点击「应用分流」也能启动服务，然后连接 VPN。仅本地分流服务必须运行，公网代理节点是可选项。

已有节点但希望只用公司 VPN 时，可在路由页选择「全局直连」。该模式将普通节点规则和应用代理统一送至直连，保留显式阻止、VPN 路由/离线保护和企业 DNS。普通 DNS 使用直连 DNS，避免继续依赖外部代理解析器。节点配置保留；直连模式下更改所选节点只保存选择，不热切换或重启当前 VPN。

集成测试启动真实 sing-box 和原生 VPN 核心，在隔离本地网络中验证无节点（fake-IP）及已有节点直连（standard）：普通域名 DNS 和 HTTP 直连、LAN 可达、已知公司离线目标不回落公网、公司 DNS 不泄露、指定节点规则不启用保存的代理、阻止规则保留。测试不改变用户正在运行的连接；真实网关与 TUN 的验收范围不变。

## 当前交付

BlueWing 增加独立的「VPN 接入」页面及本机协议核心。连接 EasyConnect 或 aTrust 后，公司 TCP 资源经用户态隧道转发；普通公网按路由模式使用所选节点或本机直连，无需代理节点也可独立使用 VPN。接入分流优先于私网、国内和应用规则，明确的禁止规则保持最高优先级。国内域名、国内 IP 和普通家庭局域网按现有规则直连。

不需要虚拟机或 EZ4Connect 进程。系统代理可覆盖遵循 Windows 代理的软件；不读取系统代理的 curl、SSH 等程序需要启用 BlueWing 现有的 TUN，或自行指定代理。ICMP/ping 不在支持范围，不能作为本实现是否可用的判断依据。

这是开发测试版，不代表已通过真实公司账号登录和 Windows TUN 验收。

首次新增/删除配置或发生端口冲突，需要用户点击「应用接入分流」，会明确重建公网核心。此操作与日常公司重连分开。端口冲突不能在普通公司重连时静默更换已注册端口。

公司「已连接」需要经正在运行的 sing-box 入口、公司 SOCKS 和当前会话返回随机探针，且公网核心 PID 不变。探针证明当前分流已生效，不代表每个办公服务器均可访问。

网络故障支持有限次数退避重试；认证失败和用户取消不自动反复登录。休眠时清除公司会话意图，唤醒后手动重新连接。接入配置可以有多个，同一时刻只运行一个公司会话。

## 本机测试版使用

1. 在旧版 BlueWing 的备份页导出 Windows 备份。退出旧版，断开 EZ4Connect 或官方VPN 接入，避免同一账号的会话相互替换。
2. 运行 `release-vpn-preview/start-preview.cmd`。启动器将数据放在 `%LOCALAPPDATA%\BlueWingConnect-VpnPreview`，不迁移旧版数据库；不要直接运行解压目录中的 exe。TUN 提权重启通过显式参数延续当前数据目录，避免计划任务丢失环境变量后切换到旧配置。
3. 如需原有代理，可导入 Windows 备份恢复节点；无需代理时可跳过节点导入，首页点击「启动直连分流」。已有节点但只需要 VPN 时，在路由页选择「全局直连」。确认普通公网直连正常。
4. 打开「VPN 接入」，选择协议，填写网关、端口和账号。网关字段填裸域名或 IP，端口单独填写，例如 `vpn.example.com` 与 `10443`。
5. aTrust 可点击「保存并获取认证方式」，在同一弹窗选择与官方网页登录一致的登录域/方式后保存。不要仅凭名称选择发现列表中的 SSO；当前只开放列表中标为支持的密码或短信方式。
6. 可按需补充公司域名、精确 IP/网段，以及固定解析，例如 `dev.corp.example 10.20.30.40`。不要把整个 `192.168.0.0/16` 都作为公司范围，否则家庭 LAN 也会匹配。
7. 点击「应用接入分流」。公网会短暂重连，完成后在公司页输入密码并连接，按弹窗输入动态码或图片验证码。凭据不应发送给开发助手或写进设计文档。
8. 默认自动处理首次出现的未受信任证书；已记录证书变化或有效期异常会停止认证。需要人工处理时可点报错旁的「检查网关证书」，进入高级选项核对指纹或配置 CA。严格模式保留手动控制。
9. 先验证浏览器访问与公网并行。要让无代理参数的命令行/其他程序也分流，再按首页现有流程开启 TUN；提权或核心重建后重新连接VPN 接入。
10. 若失败，先关闭公司连接并保留公网节点。反馈协议、状态错误码、失败目标的协议/端口以及是否开启 TUN，避免提供密码、验证码或设备会话。

## 自动验证与复现

```powershell
npm test
npm run test:vpn-core
npm run build:vpn-core
npm run build
npm run test:vpn:integration
npm run test:vpn:watch
npm run test:vpn:ui
npm run build:vpn-preview
```

`test:vpn:integration` 使用真实本机构建的协议核心、随包 sing-box 和本地受控服务，验证公司离线/非授权端口阻断、公网代理、国内域名/国内 IP/LAN 直连与资源文件切换。它没有真实登录网关。

`test:vpn:watch` 以真实数据往返验证原子替换、原地更新、损坏资源保留旧版、长连接与 PID 保持，不能只凭 HTTP CONNECT 200 判断成功。

`test:vpn:ui` 用真实 Electron BrowserWindow 和模拟 IPC，不启动产品主进程、不更改系统代理。界面截图及结果保存在被 Git 忽略的 `work/corporate-vpn-tools/ui-smoke/`。

本轮执行结果：完整 Node 测试、Go 指定包、原生核心/sing-box 联合测试、热更新实验、Electron 界面测试和构建通过。真实网关验证了 aTrust 的证书及匿名认证发现，并只读检查 EasyConnect 网关的证书，没有使用聊天中提供的登录凭据。没有执行真实账号登录、Windows TUN、办公资源及公网并行验收，也没有执行 Go race detector。

构建要求 Go 1.25.6。设置 `GO_BINARY` 可指定 Go 可执行文件；`BLUEWING_ELECTRON_DIST` 可指定已核验的 Electron 44.8.0 解压目录。默认开发缓存位于 `work/corporate-vpn-tools/`。校验值以构建生成的 `bin/vpn-core-manifest.json` 为准，不在本文复制易失效的二进制哈希。

## 当前边界

- 网络出口支持独立选择「本机直连（无需节点）」，首页、节点页和托盘保持一致。直连选择保存在路由模式中，已保存节点及其凭据保留；选择代理节点会恢复规则模式，单纯添加节点不会覆盖运行中的直连选择。
- 从无节点/直连切换到代理时，必须重新生成路由和 DNS，不能只修改 Clash 选择器。删除最后节点切换为直连并保留分流入口。受控重载不发送会断开协议会话的 `stopped` 事件；失败和显式停止仍发送终止状态。现有公网 TCP 连接会短暂重连；TUN 网卡重建仍需实机确认。
- 本地真实核心回归覆盖无节点 → 添加并选择代理 → 保留节点切直连 → 删光节点 → 加回代理，检查实际 HTTP 出口响应、公司 DNS/目标保护、协议进程 PID、错误重载及显式停止事件。此测试不代表已登录真实网关。

- 仅宣称 IPv4 TCP 办公转发。外部 UDP、ICMP、IPv6 隧道、浏览器 CAS/OAuth、客户端证书认证未开放；遇到不支持的服务器认证应明确失败。
- 不安装或修改官方 VPN 驱动。网关若要求客户端完整性检查、指定官方客户端或其他私有扩展，仍需单独适配；未知环境不能保证兼容。
- 本版本不接受公司默认路由 `/0` 或覆盖整个地址族的资源范围。授权集合端口/协议分组保留；不支持的资源协议只保留目的地保护，不转为 TCP 授权。
- 公司与家庭 LAN 使用完全相同的目标地址时，按地址分流无法识别用户意图，需要更精确的域名/端口或独立地址规划。
- 连接证明使用本机会话探针，不是全部服务器的可用性扫描。未知公司目标在尚未下发/补充时也无法自动识别。
