# 网络恢复与 DNS 归属修复

日期：2026-10-31。延续 SoftEther IPv4 包转发设计，修复审查发现的多公司 DNS 归属、代理恢复、派生缓存、连接取消及报文处理问题。

## 路由顺序

公司 DNS 和普通业务使用相同的优先级：每家公司先检查允许资源及端口，再检查该公司的目标保护，最后才进入下一家公司。公司 TCP/UDP 53 的处理位于全局 DNS 劫持前；用户阻断规则仍在公司 DNS 前。主动断开释放这家公司的规则；意外中断保留已知目标保护。

`CorporateConfig` 生成 DNS 和普通协议的同序规则，不再把所有公司的 UDP DNS 放到保护规则前。真实 sing-box 集成测试覆盖 TCP/UDP 端口限制、允许路径、掉线保留保护、主动断开释放和用户阻断。

## 系统代理生命周期

`ProxyLifecycle` 是核心配置成功、受控停止和意外退出的同步入口。核心真正就绪后才接管系统代理；使用实际运行的 mixed 端口。受控重载成功也会重新同步代理，不只在首页点击连接时同步。代次、进程 ID 和最新用户设置阻止旧的异步启用请求覆盖新状态。

关闭 BlueWing 系统代理、停止核心和退出应用都释放 BlueWing 的接管，恢复接管前的用户设置。这包括原本启用的公司代理或 PAC，不等同于无条件把 Windows 所有代理设为关闭。恢复只修改仍匹配 BlueWing 所有权的连接；外部改变的代理保留。重新接管时会记录外部修改及新增拨号连接的当前设置。

系统代理写入、释放和异常恢复串行执行。恢复成功后才释放原快照；失败保留记录供重试。普通退出不再出现先删除所有权、随后跳过恢复的问题。应用关闭时，一个 VPN 的清理失败也不会跳过其他清理步骤。

原生守护除等待 Electron 退出外，每五秒检查一次。主进程尚存但网络核心单独退出时，也能恢复失效代理；主进程收到退出事件会立即请求同一恢复逻辑。记录包含接管者 PID，旧实例的守护不会释放新实例的接管。原接管者已退出时，即使遗留子进程还占着端口，也会释放属于该接管者的代理。Windows 登录恢复仍使用独立、隐藏的程序入口。

原生恢复按 LAN / RAS 逐连接执行，保留 PAC；快照之后新增且仍使用 BlueWing 代理的 RAS 连接会回到直连，避免残留死端口。原快照若指回同一个 BlueWing 回环代理，不会把该失效代理重新启用。

意外的分流核心退出会把公司接入标为失败并保留已知公司目标保护；公网恢复不等同于 VPN 自动重登。服务恢复后可重新连接 VPN，主动断开仍会释放保护。

## 派生缓存

`known-targets.json` 和 `resources.json` 独立解析，支持 UTF-8 BOM。损坏文件以 `.invalid-*` 后缀隔离；同一文件内有效的其他公司条目仍保留。明确配置的公司目标与有效保护缓存继续使用，新登录会重新获取资源。页面显示恢复提示，普通公网初始化不因单个 VPN 派生缓存损坏而失败。

本功能不静默修复或丢弃用户的正式接入配置。配置文件或磁盘写权限异常与可重建缓存损坏是不同问题。

资源、保护目标与运行端点绑定协议、网关、账号、登录域、认证方式和 TLS 服务名的 SHA-256 身份。修改这些字段后，旧资源、探针、端点与连接意图失效，路由签名也改变。自动固定证书指纹不改变资源身份，避免首次登录固定证书后误删正在建立的端点。

两个缓存的条目写为 `{identity, value}`；旧格式在首次加载时绑定到当前配置，新格式即使程序关闭期间改了网关也不会复用旧身份。两个文件仍独立解析、隔离损坏条目。断开后的迟到事件不能重新写入资源或恢复连接状态。

## 连接取消和失效管道

管理器在请求进入串行队列前记录连接意图代次。断开全部立即取消队列内尚未开始的登录；断开单个配置只取消对应请求。会话准备阶段及自动重连也核对意图。资源撤销和界面状态先完成，随后尽力通知原生进程；已关闭的控制管道不会打断清理或从同步 fault 事件中抛出异常。

## 代理端口切换

切换系统代理端口时，先持久化原端口、新端口和事务标识；WinINet 回读确认全部连接成功后才移除旧端口别名。失败保留两个地址的所有权，避免旧端口被误认为外部代理或原始用户代理。守护按各个 LAN/RAS 当前实际使用的端口判断存活，新端口存活不代表仍使用旧端口的连接可用；部分连接恢复后，其他仍由 BlueWing 接管的连接继续保留恢复记录。

## DNS 记录和 IPv4 分片

公司 DNS 不再为 SRV、TXT 等非 A/AAAA 请求直接返回空成功结果。静态 hosts 只处理 A/AAAA，其他类型原样问公司 DNS。UDP 响应截断时，使用同一问题、同一公司解析器通过 TCP 重试；失败仍返回失败，不转系统或公网 DNS。

入口分片在端口授权前重组，回包分片在反向 NAT 前重组。每个隧道、每个方向独立限制为 64 个未完成报文、4 MiB 数据、每报文 128 片、15 秒期限；重叠或冲突片隔离到期，支持乱序及完全相同的重复片。重组后仍检查原有协议、端口和资源权限。回包在 NAT 前重组是必要的：gVisor 的 prerouting NAT 发生在其本地分片重组之前，否则大 ICMP/UDP 回包无法匹配连接。

## 真实 ICMP 与验证限制

实测发现原有具体地址的 WireGuard 端点会触发 sing-tun 的本地 ICMP echo 回复，不能将其作为公司网络连通证据。现在 UDP 与 ICMP 分别使用独立密钥、端口和回包通道；ICMP 的 sing-box 端点地址为 `0.0.0.0/32`，启用真实原始报文转发，UDP 保留具体源地址。两条本机链路共用一次 VPN 登录和同一个用户态栈，无新增系统网卡。

对应行为已核对所携带的 [sing-box 1.14.3](https://github.com/SagerNet/sing-box/blob/v1.14.3/transport/wireguard/port.go) 和固定版本的 [sing-tun ICMP forwarder](https://github.com/SagerNet/sing-tun/blob/bca4bf029237/stack_gvisor_icmp.go)。原生核心的 MIT WireGuard 维护副本将 Windows 缓冲区改为桌面默认的 65535 字节，防止较大认证帧使 UDP 接收循环因截断而退出；4096 字节双向帧有回归覆盖。

此前真实网关验证分别记录了完整链路首次小 ICMP、UDP DNS，以及原生认证链路的 2048 字节 ICMP。后续审查修复已引入固定 sing-box v1.14.3 的维护构建，修正 Windows 缓冲、分片 ID/DF 和重组校验和，并在会话返回路径重组 ICMP。实际 sing-box、认证链路、原生 NAT 和模拟公司网络的隔离完整链路现已通过 8192 字节 ICMP、3072 字节 UDP 及八路交错 UDP；本轮尚未重复真实公司网关大报文验收。详见 [修复记录](../review/network-audit-fixes-2026-10-31.md)。

## 验证边界

- 应用测试覆盖代理释放、重复退出、PAC、外部修改、新 RAS、失败重试、异步同步失效、缓存隔离和公司保护状态。
- 原生测试覆盖持久化恢复、父进程仍存活时的周期恢复、暂时失败重试、孤儿子进程、新实例所有权与恢复计划。
- 真实 sing-box 集成覆盖公司 DNS 优先级和协议一致性；真实 preload / React 测试覆盖恢复提示与核心中断状态。
- 保留原有首包 ICMP/UDP、TCP 和多公司回归。未实际重启用户电脑，未强杀用户当前网络核心。
- TUN 接受本地 TCP 连接和 SSH 服务实际握手仍是不同阶段；Xshell 的短暂绿色不能替代真实业务握手验证。
- 本轮应用测试 199 项；原生测试包含 DNS 记录/TCP 重试、分片授权/乱序/重叠/过期、双向大帧和大 ICMP/UDP 反向 NAT。真实网关测试不在普通回归中自动执行。
