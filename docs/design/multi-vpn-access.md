# 多 VPN 接入

## 使用方式与优先级

VPN 接入列表允许同时连接多个配置。每条接入显示独立的连接状态、验证码、错误与重试状态；断开按钮仅停止当前接入，顶部的「断开全部」才停止所有接入。正在连接的配置可以只读查看，其他未连接配置可以编辑。

「高级分流」增加分流优先级，范围 1–9999，数字越小越优先，旧配置缺省为 100。同值时沿用配置的保存顺序，改名不会改变顺序。此字段随普通配置导入和备份保存。

资源和公网策略分别处理：

1. 每家公司的明确域名、IP、固定解析和网关资源走该公司的隧道。
2. 不同公司的明确资源重叠时，按接入优先级选择；没有按失败结果猜测另一个公司的规则。
3. 已连接接入中优先级最高的一条决定普通流量的「智能分流 / 全部走 VPN / 自定义」策略。其他接入仍提供各自的公司资源，不能覆盖该普通流量策略。界面显示当前策略来源，查看其他接入时也展示实际的普通流量出口。
4. 智能分流保留国内公网本机出口，国外沿用已启用的公网代理；全部走 VPN 时公司和国内走 VPN，国外仍优先使用已开启的代理。没有代理节点时，可以本机直连并使用公司 VPN。

异常掉线保留该接入已知资源的保护规则，避免它们流入另一家公司或公网。用户主动断开或点击恢复普通分流会释放这条接入的保护；此后重叠资源可由剩余已连接接入处理。其他公司的非重叠资源持续可用。新启动程序清除过期运行状态，保留保存的资源和配置，不假装旧隧道仍连接。

## 运行结构

`CorporateVpnManager` 负责会话集合、共享分流生命周期和快照；`CorporateVpnSession` 保留单会话状态机。每个使用过的配置单独启动一个 `bluewing-vpn-core.exe`，只给它配置当前公司的 SOCKS 和 DNS 端点。上游存在进程级 TLS / 认证状态，因此不能让多个登录复用同一个原生进程。

每条会话独立持有 generation、验证码、超时、保存的凭据身份和重试计时器。验证码响应绑定 profileId + challengeId + generation，拒绝过期或归属不唯一的响应。取消其中一条不会取消另一条。受控的共享分流核心重建不取消仍在进行的另一条身份验证；就绪探针必须通过当前核心、当前公司的随机 nonce 才确认成功。

端口冲突仅重新分配冲突配置的端口，不移动已连接公司的端点。新增接入、端口或策略结构变化需要重建共享分流核心，连接操作自动完成，无需再点应用。核心重建可能中断通过该共享核心的应用 TCP 连接，原生 VPN 会话独立保留；配置无变化的连接、单条断开和一般掉线恢复仅热更新规则文件。

退出会停止所有会话和本地端点。单条断开保留其原生进程，以允许由该进程承载的本机直连流继续使用；后续连接可复用端点。未使用的配置不会启动原生进程。每多连接一家公司会增加一个原生核心进程的开销，不需要虚拟机。

## 未知私网目标

明确公司资源优先匹配，不进入自动发现。智能分流的未知 RFC1918 IPv4 TCP 目标进入一个随机认证的回环 SOCKS 分派器，按连接优先级尝试启用了自动识别的接入。

系统代理模式下，先给 Windows 路由 800ms 的连接机会，保留本地 LAN 和官方 VPN 路由；实际 TUN 模式不执行这个未绑定拨号，避免进入自身。原生核心随后验证物理出口及本接入隧道。每条候选最多 3.5 秒，VPN 尝试总计不超过 15 秒；连接成功前不发送应用数据，成功后不再自动切换隧道或重放请求。

成功候选仅缓存精确目标和端口 60 秒，最多 256 条；接入、generation 或端口变化使缓存失效。历史自动识别记录仍按公司身份保存并用于失败保护，不会当作永久的归属规则。不猜测整个公司的网段，不扫描未访问的目标。

自动发现不能解决地址相同且端口相同的业务身份歧义，也不能凭空得知特殊公司域名的私有解析；这类目标需在对应接入的高级分流补充。公网公司 IP 同样使用明确规则。当前隧道转发支持 IPv4 TCP，UDP / ICMP 不因多连接而新增支持，不能用 ping 结果判断 SSH / HTTP 分流。

## 验证

自动化入口：

```powershell
npm test
npm run test:vpn:integration
npm run build
npm run test:vpn:ui
```

- 会话测试覆盖独立原生端点、并行身份验证归属、单条取消 / 重试、活动配置只读、同级顺序、备份优先级及单条端口冲突。
- 分派器测试覆盖候选失败后回退、应用数据仅发送一次、公网地址拒绝和候选移除。
- 实际 sing-box 集成覆盖两家公司各自资源、重叠优先级、异常保护、主动释放、未知私网回退、国内直连和国外代理，验证不需要重启共享核心。
- Electron 界面测试覆盖两个独立验证码、两个已连接状态、编辑未连接接入、优先级显示、单条断开与全部断开，同时保留左右独立滚动验证。

2026-10-27 隔离实测使用本机保存的示例 A EasyConnect 与示例 B SoftEther 配置，独立混合端口，不改当前 Windows 代理、路由或正式配置。两条原生进程 PID 不同，两条接入同时就绪：`10.203.18.40:22`、`10.203.17.117:22` 均返回 SSH banner；国内 HTTPS 返回 200，国外测试返回 204。主动断开示例 A 后，示例 B 的已有 SSH 连接仍开着，新连接也返回 banner。此项是握手与短时连接验证，不代表完成业务登录、长期稳定性或所有网络切换验证。

同次实测的开发域名返回 502：测试所复制的示例 A配置没有保存该域名或固定解析，且网关没有下发它，域名走了普通 DNS 并超时。此结果单独记录，不能把两条 IP 的验证扩展为所有公司域名成功。将特殊域名加入对应接入仍是必要的用户配置。

内置 aTrust 的可信终端认证限制没有随多连接解决。本次没有将该网关标记为可用；官方 VPN 的系统代理共存修复包含在同一版本，实际 TUN 与各类官方客户端的组合仍需分别验证。
